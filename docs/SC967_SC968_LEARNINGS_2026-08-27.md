## Recurring theme: strict unknown-property parsing

Three separate defects (#3, #4, #5) were the same class: a Jackson mapper rejecting a
field it did not declare, surfacing as an opaque 422 or a swallowed exception. Whenever a
capture call fails with 422 and no useful message, suspect field binding first.

Regression tests now cover this and run in `chromascape_ai_runtime_tests`:
- `RoutineApiDtosWireFormatTest` — parses the exact payloads `CaptureSessionClient` emits.
- `CaptureOperationDispatcherParseTest` — parses the exact JSON persisted in
  `routine_capture_operations.request_json`.

## Operational learnings

- **The console transcript is UTF-8 with BOM, not UTF-16LE.** The previous handoff said
  otherwise; decoding it as UTF-16 yields pure mojibake.
- **Never run two acceptances at once.** `finish-sc967-sc968.ps1:247` archives
  `output\sc968` at startup, so a second launch moves the live run's signing keys and gate
  logs out from under it mid-run.
- **Kill by pattern, and match the wrapper you actually launched.** A restart script that
  matched only `finish-sc967-sc968.ps1` left an orchestrator alive and killed just its
  children, producing a misleading gate failure.
- **The acceptance database must be recreated, not reused.** The outbox is durable, so any
  killed run leaves work that the next run will execute.
- **`git status` on micro6 times out on DrvFs.** Use scoped pathspecs; a timed-out
  `git add` silently leaves the repo dirty, which then aborts the next run via
  `Require-CleanRepository`.
- **`/scripts/*/` is gitignored**, but `scripts/sc968/*` is already tracked, so commits
  work; the "paths are ignored" hint is advisory noise.
- **Maven repo was discarded every run** (250 MB re-resolved). Moved to `output\sc968-m2`,
  outside the archived tree — `0db4566`. Saved ~4 minutes per cycle.

## Known weaknesses, deliberately not fixed

- **`prepareStart` latches.** Once a start attempt fails without recording a
  `recording_id`, every retry takes the `execute=false` branch and reports `UNCERTAIN`
  forever. It cannot self-heal. This is a design change, not a bug fix.
- **The capture transport sends one HTTP request per 600 ms game tick**, one spool entry
  per POST. Fixing the log level made it keep up, but there is no batching headroom.
- **`OpenRuneReplayPlugin` has the same wrong `@Subscribe` import** as the capture plugin
  had; its handlers are dead. Out of scope.
- **Tick debugger `SessionStartRequest` rejects an unknown `type` field.** Unrelated to
  the capture path (`CaptureRecordingGateway` calls `DebugSessionService` in-process), so
  left alone.
