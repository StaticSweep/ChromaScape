## Findings

### F1 — P1: current review labels cannot pass the current backend contract

`src\main\resources\static\js\mouse-video.js` lines 192–194 append a `provenance` field
to every review-mode cursor label. `MouseVideoCorrectionContract` still declares
`corrections/v1`; neither its common nor cursor field allowlists contain that field. Its
normalizer rejects every unknown field at lines 201–207. The controller maps that exception
to HTTP 400.

Reproduction used `labelValues('hidden', {blind:true})` and the actual exported client
`buildCorrection` function to generate the submitted label. Compiled the current Java validator
and ran it on that exact JSON: `INVALID_REQUEST: Correction 0 carries unknown field 'provenance'`.
Removing only `provenance` made the same correction pass. The current stub browser harness
instead accepts arbitrary fields and returns the not-yet-implemented `corrections/v2` contract,
which masks this mismatch.

Required: implement the compatible, validated server review/provenance contract and its
revision/export/converter handling, then test the actual review POST. Merely trusting arbitrary
client claims or stripping provenance while claiming independent evidence is not a resolution.
This overlaps planned CP25I8–I11 but blocks treating the current UI as a usable completed flow.

### F2 — P1: retry UUID is reused with edited content after an uncertain write outcome

`sendReviewSnapshot` at lines 1603–1634 constructs a new snapshot on every attempt, while
`pendingReviewRequestId` persists after an error. The pending identity does not retain its exact
submitted body, context and base revision.

Fresh real-Chromium reproduction with controlled stub failure: accept/store the first write and
abort its response, add another label, then save again. Two POSTs used the **same UUID** with
different bodies and correction counts **2 then 3**. The stub enforced the existing server's
digest rule and returned a conflict. The draft is retained, but automatic idempotent recovery
is broken and requires user conflict recovery.

Required: retain the exact uncertain request body/context/base with its UUID, retry that snapshot
until acknowledged or reconciled, then send later edits under a new UUID. Preserve the existing
serialized happy-path queue and snapshot-version acknowledgement. Add lost-response plus
later-edit tests, not only delayed successful responses. CP25I3 is not fully complete yet.

### F3 — P1 for independent qualification: toggling Blind cannot erase prior exposure

`mouse-video-review-core.js` line 491 derives `INDEPENDENT` solely from the current Blind boolean.
There is no persistent suggestion-exposure state for the frame/session. Refusing an existing
assisted draft does not address a reviewer who saw the prediction without accepting a label.

Fresh browser reproduction started with empty history: display the prediction on frame 0,
switch Blind on, manually label that same frame 0, then save. The draft passed the client guard
and sent one revision with `without-suggestions` and `provenance: INDEPENDENT`.

Required: preserve exposure/protocol history, prevent an exposed session from being recast as
independent, and use the planned authoritative review-session policy/ledger before qualification.
Turning the overlay off protects future display; it cannot make already-seen predictions unseen.
CP25I5/CP25T2 should not be interpreted as complete independent-provenance acceptance.
