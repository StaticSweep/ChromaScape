## Findings

### A1 — Memory-overallocation guard fails reproducibly on this host

`MouseVideoResourceLimitsTest.allocationAboveMemoryBudgetIsKilled` failed both in the scoped run
and an independent rerun. The production runner's bounded diagnostic reproduced a successful
256 MiB allocation under a 64 MiB resident-memory ceiling:

- `memory.max = 67108864`; `memory.peak = 67108864`.
- `memory.swap.max = max`; `memory.swap.current = 207413248`.
- Child exit code 0, complete output, no OOM kill.

The resident-memory ceiling is enforced. The test's stronger assertion that the allocation must
be killed does not hold because swap remains unlimited. The systemd command sets `MemoryMax`,
`CPUQuota` and `TasksMax`, but no swap ceiling. Resolve the intended resident-versus-total-memory
policy and implement/test it before counting the resource gate as passed; do not relabel this
failure a passing test. Evidence: `resource-rerun`, `memory-probe.log`, and the production
`MouseVideoProcessRunner.java` systemd launch arguments.

### A2 — Imported playback leaves an indefinite tick-loading indicator

Fresh browser reproduction: open `/replay`, choose “From others”, play an imported source, wait
for media readiness. The player correctly says “no game ticks”, but `loadingTickData` stays
visible and `noTickDataMessage` incorrectly says the recording predates tick tracking.
`playExternalRecording` clears tick cards and shows the message without hiding the loader.
Fix the imported-media terminal state and wording. Evidence: `replay-tick-state.json` and PNG;
source: `src\main\resources\templates\replay.html`.

### A3 — FA12 remains unqualified for the current V7 method

V7 implements appearance-gated starts and periodic whole-frame rechecks; it is not merely the
old V5 implementation. The current tracker tests include resting cursors, disappearance,
look-alike starts and takeover behavior. The fresh development probe uses one already-spent
synthetic dev clip, twice; it cannot establish held-out real-footage accuracy, cut accuracy,
or the required 99% recall across supported cases. No held-out footage was run or used to tune.
Earlier V5/V6 results are historical, not measurements of current V7 quality.

### A4 — Planned review mode and remaining qualification are still open

The working page has exact-frame point/region corrections, manual save, revision history and
conflict recovery. The planned trail, quick-label keyboard controls, prioritized review queue,
autosave and blind labelling mode are absent from the current page/script. Basic arrow-key
frame navigation exists and passed browser checks.

The product YouTube route exists and refuses explicitly while disabled. Its acquisition runner
uses the same no-network restricted launcher; a distinct constrained-egress acquisition path
and its live qualification are still needed. Verified local downloader hash/help compatibility
does not qualify the product route. Target-region production explicitly emits `UNSUPPORTED`;
additional action/pause/camera/target qualification must not be counted as complete from cursor
tests. Windows and a genuine micro6 capture-to-label session were not exercised on this Fedora
audit host.
