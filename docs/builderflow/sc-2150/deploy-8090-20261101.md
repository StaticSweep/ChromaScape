Executes the precondition established by `rollout-rehearsal-20261101.md`: the old database could
not accept `main`, so it was preserved and a fresh one was built from `main`'s migrations.

`CHROMASCAPE_FEDORA_RUNTIME_PROJECT_DIR` in the repository's `.env.local`, or simply starting that
checkout again. The old database is one `ALTER DATABASE … RENAME` away.

## Local files the runtime needs (both excluded from git by this clone)

- `scripts/mcp-bridge/` — required by `McpBridgeLifecycleManager` (startup fails without it).
- `scripts/start-fedora-dev.sh` — the canonical Fedora launcher; excluded via `.git/info/exclude`.
  The copy in the runtime checkout adds `CHROMASCAPE_MOUSE_VIDEO_*` to the `.env.local` whitelist,
  which otherwise forwards only source, stabilization and toolchain keys, so the SC-2150 surface
  would stay dark after a restart even when the operator enabled it.

## Rollback

1. **Code only:** start the previous checkout again
   (`CHROMASCAPE_FEDORA_RUNTIME_PROJECT_DIR` in the repository `.env.local` still points at
   `ChromaScape-sc663-runtime`), or repoint it back.
2. **Code + schema:** `ALTER DATABASE chromascape RENAME TO chromascape_main_20261101;` then
   `ALTER DATABASE chromascape_pre_main_20261101 RENAME TO chromascape;` and restart.
3. **From the snapshot:** `pg_restore -d chromascape build/db-snapshots/live-pre-main-20261101T160402Z.dump`.

## Operational note

The first start attempt failed with `database "chromascape_fresh_rehearsal" does not exist`: a
`SPRING_DATASOURCE_URL` exported during the earlier rehearsal leaked into the shell that launched
the app, and the launcher deliberately does not override non-empty process environment values.
Start 8090 from a clean environment; the `.env.local` whitelist then governs.
