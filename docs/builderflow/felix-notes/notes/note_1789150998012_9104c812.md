Reproduced from the SC-810 planning note (`note_1787866248248_c4812448`) — unchanged, no new design decision.

```mermaid
flowchart LR
    CAT[Micro6 catalog task] --> RES[Entry-point and closure resolver]
    SRC[Clean pinned Micro6 source tree] --> RES
    BUILD[Commit/tree + build + artifact digest] --> RES
    RES --> IDX[Versioned symbol and range indexer]
    IDX --> MAN[Signed TaskSourceManifest]
    SRC --> CAS[Content-addressed immutable source snapshot]
    MAN --> CAS
    LAUNCH[Launcher/Mule artifact attestation] --> RUN[SC-609 run and recording]
    MAN --> VERIFY[ChromaScape manifest verifier]
    CAS --> VERIFY
    RUN --> VERIFY
    VERIFY --> REF[Verified run-to-snapshot reference]
    REF --> API[Authorized read-only debugger source API]
    API --> UI[/debugger source view]
```

Trust rules (unchanged from planning): the manifest is authoritative only when signature/checksum,
commit/tree, build ID, artifact digest, and snapshot ID agree; the snapshot is immutable and
content-addressed; ChromaScape fails closed on missing proof or mismatched identity; no fallback
to current source, a branch, a tag, or a caller-provided location is allowed.

As-built this session: the packaged `Micro6BuilderExecutorServer` proves its own running-artifact
identity via `CodeSource`-based verification (not just the generator's self-check at promotion
time) — see `closure-plan-phase8-packaged-runtime-gate-20260911.md` in ChromaScape-consolidation's
`docs/sc810-evidence/`.
