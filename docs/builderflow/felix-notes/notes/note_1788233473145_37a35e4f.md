## Outcome

After this change:

1. Persisted recovery never passes a redacted OrchestrationRequest to a gateway as if it were the original request.
2. An ambiguous reservation without a lease can be reconciled by stable request identity without reserve or dispatch retry.
3. PostgreSQL proves concurrent identity and authority ownership using committed independent transactions.
4. PostgreSQL proves root and normalized writes roll back atomically when receipt, event or terminal insertion fails.
5. Restart proof uses the Flyway-created schema and a second application/persistence context after commit.
6. Human authority verification cannot be disabled by selecting an alternate production-store constructor.
7. The V23-versus-V24 decision has durable environment evidence.

## Finding 2 — reservation uncertainty without a lease must be reconcilable

Current behavior enters NEEDS_RECONCILIATION if gateway.reserve throws or returns an ambiguous outcome, but reconcile always requires a persisted lease. That state can never query the remote reservation owner.

Decision:

Add an explicit gateway operation:

reconcileReservation(GatewayCorrelation correlation)

This operation is lookup-only. It is bound by orchestration/request/idempotency/envelope identity and cannot reserve, dispatch, switch provider, change request identity or create continuing authority.

AccountBuilderOrchestrationService.reconcile branches on normalized state:

- If a persisted lease exists, call the existing leased reconciliation operation.
- If no lease exists, authority is durably consumed, and the orchestration is NEEDS_RECONCILIATION, call reconcileReservation.
- If no lease and no authority exist, make no gateway call; return the quiescent state or a reviewed proven denial.
- Never call reserve or dispatch from reconciliation.

Receipt outcomes:

- Proven no reservation/task exists: persist a proven terminal DENIED or FAILED outcome with RESERVATION_REJECTED and retryAllowed=false because the authority is already consumed.
- Proven reservation exists with an exact valid lease: append the receipt and persist the lease while remaining NEEDS_RECONCILIATION. Do not return to RESERVED and do not dispatch. A later leased reconciliation may prove terminal state.
- Proven terminal remote outcome: persist that terminal result.
- Missing, malformed, cross-request, stale or ambiguous response: remain NEEDS_RECONCILIATION with retryAllowed=false.
- Expired or mismatched returned lease: remain quiescent with LEASE_EXPIRED or FENCE_MISMATCH evidence; no delivery.

Update legal transition/receipt validation so NEEDS_RECONCILIATION may acquire a first proven lease but may transition only to itself or a proven terminal state.

## Finding 3 — PostgreSQL concurrency proof

The existing AccountBuilderOrchestrationConcurrencyTest is in-memory only. Keep it as a fast unit test, but add committed PostgreSQL concurrency coverage.

Create:

C:\Dev\IdeaProjects\ChromaScape\src\test\java\com\chromascape\web\gameplay\orchestration\accountbuilder\AccountBuilderOrchestrationPostgresConcurrencyTest.java

Use the same Flyway-created isolated schema as the JPA integration suite. Do not annotate the class or methods with one shared Transactional transaction.

Each worker must use:

- an independent transaction;
- an independent EntityManager/persistence context;
- a CyclicBarrier so claims reach the database concurrently;
- bounded Future timeouts to prevent a hanging test.

Required races:

1. Eight identical claims: one created=true, seven created=false, one root row, one binding row and one creation event.
2. Same requestId with different orchestration/fingerprint: one owner and one IDEMPOTENCY_CONFLICT, no partial loser rows.
3. Same idempotencyKey with different request/orchestration: same result.
4. Two committed orchestrations consuming the same valid signed authority: one owner and one AUTHORITY_ALREADY_USED.
5. Two transitions racing on one orchestration: monotonic event and receipt sequences with no duplicates or gaps.
6. Same orchestration racing two different authorities: exactly one authority row and the loser fails closed.

Assert final rows through a separate committed read transaction.
