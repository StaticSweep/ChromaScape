# Integrated implementation and verification plan

## Scope and exclusions

The task is the clean-worktree integrated proof for SC-1452, SC-967, and SC-968. It includes native Contracts reproducibility, LeeuwBot candidate-worker verification, Micro6-accept focused and harness gates, RuneLite capture safety gates, explicit clean ChromaScape restart/debugger smoke test, three sidecar-gated human captures, fresh PASS manifests, artifact hashing, and truthful Felix/Shortcut reconciliation.

Protected dirty checkouts and excluded Micro6 directories are never modified or used for final evidence. No push, PR mutation, production promotion, historical row import, direct input dispatch, real-account hash bypass, blind retry, or SC-1498 closure is allowed.

## Given/When/Then acceptance criteria

- Given exact integrated roots, when the preflight table checks heads, source cleanliness, no merge/rebase, locks, gates, and contract identity, then provenance is recorded and no original checkout is selected.
- Given isolated Maven repositories, when Contracts clean install is run twice, then tests pass and JAR bytes, contents, and timestamps match.
- Given the integrated candidate worker, when native Go gates run, then all required compile/checkstyle/candidate/shadow/SBOM checks are executed and any failure stops certification.
- Given Micro6-accept and RuneLite, when native capture identity and safety suites run, then client/build/source provenance is exact, revision-sensitive, and read-only.
- Given the clean ChromaScape boot, when root and debugger are opened, then all required panels render without JavaScript errors, clean Micro6 and CZC8518C27 are visible, and no historical data or input dispatch is introduced.
- Given the login-ready sidecar, when each phase performs exactly one Net action on one Fishing spot, then completed captures have the expected sequences and zero queued events.
- Given fresh runtime documents, when manifests and artifacts are independently scanned and hashed, then both manifests are PASS, all safety values are false/0, hashes are internally valid, and identities are current.
- Given current-build PASS evidence, when tracker handoff occurs, then SC-1452 can be placed in review only if all current delivery criteria pass, SC-967/SC-968 remain In Progress unless SC-1498 is separately proven or explicitly follow-on, and no push occurs.
