Minimal OpenAPI 3.1 for the two read-only Micro6 source endpoints the planning note specifies
(`GET /api/v1/source-manifests/{taskKey}`, `GET /api/v1/source-snapshots/{snapshotId}/files/{fileId}`),
as actually implemented in `Micro6BuilderExecutorServer` (`SourceManifestHandler`, registered at
`/api/v1/source-manifests` and `/api/v1/source-snapshots` — see
`runelite-client/src/main/java/net/runelite/client/plugins/microbot/accountbuilder/integration/builder/Micro6BuilderExecutorServer.java:642-643`
in `micro6-sc810-integration`).

```yaml
openapi: 3.1.0
info:
  title: SC-810 Micro6 Source Manifest API
  version: "1"
paths:
  /api/v1/source-manifests/{taskKey}:
    get:
      summary: Fetch the signed TaskSourceManifest for a task key
      parameters:
        - name: taskKey
          in: path
          required: true
          schema: { type: string }
      responses:
        "200":
          description: Verified manifest with integrity metadata and snapshot reference
        "404":
          description: SOURCE_UNAVAILABLE / SOURCE_PRUNED / unknown task
        "409":
          description: SOURCE_BUILD_MISMATCH
  /api/v1/source-snapshots/{snapshotId}/files/{fileId}:
    get:
      summary: Fetch one manifest-allowlisted file's content, hash-verified before return
      parameters:
        - name: snapshotId
          in: path
          required: true
          schema: { type: string }
        - name: fileId
          in: path
          required: true
          schema: { type: string }
      responses:
        "200":
          description: UTF-8 file content plus metadata; ETag = declared content hash
        "404":
          description: unknown fileId (resolved only through the signed manifest; never a
            caller-supplied path — absolute/traversal/symlink-escape inputs fail this way too)
        "410":
          description: SOURCE_REDACTED / SOURCE_PRUNED
```

Stable failure states from the planning note (`SOURCE_UNAVAILABLE`, `SOURCE_REDACTED`,
`SOURCE_PRUNED`, `SOURCE_GENERATED_ONLY`, `SOURCE_BUILD_MISMATCH`, `SOURCE_MANIFEST_INVALID`,
`SOURCE_CONTENT_HASH_MISMATCH`, `SOURCE_ACCESS_DENIED`, `SOURCE_INDEX_PARTIAL`) are mapped onto
these HTTP responses at the implementation's discretion per case; this contract intentionally
does not re-litigate that mapping, which is exercised by the endpoint test suite referenced in
`docs/sc810-evidence/` rather than restated here.
